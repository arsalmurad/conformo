# Building Conformo from source

This is for people working on Conformo itself, not people who just want to
use it. If you only want to make an invoice, use the live app or `npm i
@conformo/cli` instead — see the [README](../README.md).

## Quick start

    npm install
    npm run typecheck && npm run test
    npm run build:sample        # -> out/invoice.pdf + out/factur-x.xml, plus one hybrid PDF per profile

The validation gates need Python 3 (`py` on Windows, `python3` elsewhere), Java 11+ (only for the official KoSIT validator in the
conformance run) and the pinned Python packages:

    pip install -r tools/requirements.txt

Every third-party artefact (CEN, KoSIT, Peppol, SchXslt2, factur-x, the SaxonJS runtime) is declared once, with version and SHA-256 or
commit pin, in `tools/artefacts.manifest.json`. Fetching is idempotent and cached in `tools/artefacts/.cache` (set `CONFORMO_ARTEFACT_CACHE` to move it):

    npm run artefacts:fetch -- --group build,corpora,java   # also: browser
    npm run schematron:compile   # rule sets -> packages/validate/artefacts/*.sef.json.gz + the XSDs + rulesets.json
    npm run saxonjs:fetch        # browser runtime (gitignored); see docs/KNOWN-GAPS.md if downloads.saxonica.com is blocked
    npm run validate             # official XSD + Schematron on every fixture, PDF/A audit of every profile's PDF

Other gates:

    npm run conformance          # regenerates docs/CONFORMANCE.md (add -- --strict to fail on unexplained findings)
    npm run pack:smoke           # npm pack every package, install into a fresh project, run all docs code
    npm run coverage:generate    # docs/EN16931-COVERAGE.md; schema:generate and openapi:generate likewise
    node tools/check-sizes.mjs   # bundle budgets

To run the app locally:

    npm run dev --workspace=packages/ui

The end-to-end gate (creates a real invoice through the UI, asserts the downloaded PDF passes `tools/validate.py`) needs a Playwright browser once:

    npx playwright install --with-deps chromium
    npm run e2e

To try it in Docker instead (builds the app and serves it on `:8080`):

    docker compose up --build

To run the standalone validator page or the docs site on their own:

    npm run dev --workspace=packages/validator-page
    npm run build:compliance-data && npm run docs:build   # writes packages/docs-site/dist/

## Architecture

    packages/core            EN 16931 model, money, tax, totals. Zero deps.
    packages/formats          CII, UBL, XRechnung, Peppol BIS serializers.
    packages/pdf              PDF/A-3 writer with embedded XML. Depends only on pdf-lib.
    packages/parse             Reads a Factur-X/ZUGFeRD PDF or CII/UBL/XRechnung XML back into an Invoice.
    packages/validate          Runs the official Schematron (SaxonJS) and XSD (libxml2-WASM), auto-detects syntax/profile, plain-language messages.
    packages/toolkit           create / validate / convert / parse / explain / requirements in one Node API. The CLI, MCP server and HTTP API call it.
    packages/schema            zod + JSON Schema for the Invoice (used by the MCP server and the HTTP API).
    packages/server            Optional stateless HTTP API (Hono) with generated OpenAPI 3.1.
    packages/compliance-data   Sourced dataset of per-country e-invoicing mandates.
    packages/ui                The web app.
    packages/validator-page    Standalone client-side validator, separately deployable.
    packages/docs-site         Static docs site generated from the compliance dataset.
    packages/cli               create / convert / validate / parse / explain / requirements.
    packages/mcp-server        7 tools over MCP stdio and Streamable HTTP.
    tools/                     Build and validation harnesses.
    fixtures/                  Test invoices. Synthetic data only.

## README pictures

The GIF and screenshots in the README (`docs/media/`) are recorded from the real built app and validator, never drawn
by hand. After a UI change, regenerate them (needs ffmpeg and Playwright's Chromium):

    npm run readme:media

This also writes `docs/media/social-preview.png` (1280x640), the image for the repository's Settings > General >
Social preview, which is what link previews on LinkedIn, Slack and X show.

## Definition of done for any change

- `npm run typecheck` clean, strict mode, no `any` added to public APIs
- `npm run test` passes, and new behaviour has a test that would fail without it
- `npm run build:sample && npm run validate` both pass
- No new runtime dependency in core or formats
- Public API documented with the BT/BG identifier it maps to

See [`CONTRIBUTING.md`](../CONTRIBUTING.md) for the full contract
(non-negotiable invariants and anti-goals). `packages/pdf/src/pdfa.ts` and
the element order in `packages/formats/src/cii.ts` encode non-obvious
requirements found the hard way (see `docs/pdf-traps.md`); rerun
`npm run build:sample && npm run validate` after touching either.
